# 每日饮品记录小程序：产品设计文档

## 1. 产品定位

这是一个帮助用户记录每天喝了什么，并逐步追踪饮品健康摄入的个人饮品记录小程序。

用户可以记录某一天、某个时间喝了什么饮品，包括品牌、饮料款式、照片、糖分、冰度、甜度和小料等信息。MVP 只服务个人记录，每条记录只对应一杯饮品。未来基于饮品的营养数据，计算每日或一段时间内的能量、糖量、咖啡因等摄入量。

产品可以理解为“饮品日记 + 饮品菜单数据库 + 健康摄入统计”。

## 2. 核心使用场景

用户在购买饮品后：

1. 选择或搜索品牌。
2. 选择饮料款式。
3. 选择糖度、冰度和小料。
4. 上传饮品照片。
5. 记录饮用时间和地点。
6. 查看当天以及历史饮品记录。
7. 根据已录入的营养信息查看糖量、能量和咖啡因摄入。

## 3. 核心概念

### 3.1 饮品品牌

饮品所属的品牌，例如喜茶、奈雪、星巴克或便利店品牌。

### 3.2 饮品款式

品牌菜单中的具体饮品，例如某一款奶茶、咖啡、果茶或气泡水。饮品款式应保存可用于健康计算的基础营养信息。

### 3.3 饮品记录

用户实际喝过的一杯饮品。记录引用一个品牌和饮品款式，并保存本次购买时的规格、糖度、冰度、小料、照片和时间。

### 3.4 菜单数据

品牌和饮品款式组成可复用的菜单数据库。菜单数据与用户实际记录分离，避免每次记录都重复填写饮品信息。

## 4. 饮品记录信息

每条饮品记录建议包含：

- 饮用日期
- 饮用时间
- 品牌
- 饮料款式
- 杯型或规格
- 照片
- 糖度
- 冰度
- 小料
- 地点（可选）
- 备注（可选）

其中糖度、冰度和小料需要支持“未选择”状态，避免用户在信息不确定时无法保存记录。

## 5. 健康摄入计算

每个饮品款式需要逐步建立营养数据，例如：

- 能量
- 糖量
- 咖啡因
- 碳水化合物（后续可选）
- 脂肪和蛋白质（后续可选）

健康摄入计算应基于“饮品款式 + 杯型/规格 + 糖度 + 小料”进行，而不是只根据品牌或饮品名称估算。

营养数据采用“官方数据优先、无官方数据时使用估算”的原则。对于估算结果，必须明确显示“估算值”，不能把估算结果伪装成精确值。没有足够信息进行估算时，应显示“暂无数据”。

## 6. 第一版 MVP 功能

### 用户功能

- 登录或进入小程序
- 查看个人饮品记录
- 查看个人基本信息

### 菜单功能

- 搜索品牌
- 搜索饮品款式
- 查看饮品详情
- 查看可选糖度、冰度、小料和规格
- 在菜单中标记暂无该饮品

### 记录功能

- 创建饮品记录
- 选择日期和时间
- 选择品牌和饮料款式
- 选择糖度、冰度、小料和规格
- 上传饮品照片
- 填写地点和备注
- 编辑和删除记录
- 按天查看饮品时间线
- 查看历史饮品记录

### 健康统计功能

- 查看当天饮品数量
- 查看当天能量、糖量和咖啡因（有数据时）
- 查看周、月汇总（后续）
- 标识估算值和暂无数据的记录

## 7. 建议的数据关系

```text
用户 User
 └── 创建多条饮品记录

品牌 Brand
 └── 包含多个饮品款式

饮品款式 Drink
 ├── 属于一个品牌
 ├── 包含规格和营养数据
 └── 包含可选糖度、冰度和小料

饮品记录 DrinkRecord
 ├── 属于一个用户
 ├── 引用一个品牌和饮品款式
 ├── 保存本次选择的规格、糖度、冰度和小料
 ├── 保存照片、时间、地点和备注
 └── 保存本次计算出的营养摄入快照

营养数据 Nutrition
 ├── 能量
 ├── 糖量
 └── 咖啡因
```

## 8. 菜单数据建设

“市面上所有常规主流品牌的菜单”是一个持续维护的数据工程，而不是一次性录入即可完成的功能。菜单可能因为地区、门店、季节、活动和配方调整而变化。

建议采用以下方式：

- 先建立有限范围的主流品牌和高频饮品。
- 菜单数据保存品牌、饮品名称、规格、可选项和更新时间。
- 每个饮品款式允许存在地区或门店差异。
- 对已下架饮品进行下架标记，不直接删除，以保留历史记录。
- 为菜单数据保留来源和可信度。
- 支持用户创建“自定义饮品”，解决暂未录入或非连锁饮品的记录需求。
- 预留后台管理能力，用于新增、修改、下架和审核菜单数据。

不建议把所有品牌菜单作为第一版上线前置条件，否则会显著延迟产品验证。第一版可以使用少量品牌 + 自定义饮品，先验证记录习惯和健康统计需求。

## 9. MVP 决策

- MVP 只做个人记录。
- 一条记录只对应一杯饮品。
- 允许用户创建自定义饮品。
- 营养数据以官方数据为优先；无官方数据时可以使用明确标注的估算值。
- 容量由用户手动填写（毫升），不是必填。
- 甜度、冰度和小料允许自由填写，均可留空。
- 地点由用户手动填写，不请求定位权限。
- 暂不加入每日提醒和摄入超标判断，只展示可追溯的数据。
- 菜单项目保留地区、来源、更新时间和下架状态；下架项目仍供历史记录展示，但不能用于新记录。
- 营养值只有在饮品、容量、甜度、冰度和小料完全匹配的数据存在时才展示；不对未提供的选项擅自推算。

## 10. 数据范围与实现边界

- 当前内置菜单是用于验证流程的少量示例项目，菜单名称与在售状态需在发布前按目标地区核验；当前没有内置经核验的官方营养数据。
- 小程序将记录和照片保存在当前设备本地。当前没有账号体系、跨设备同步或云端备份。
- 自定义饮品可保存用户填写的营养估算，并标注为“估算值”。

## 11. 产品一句话介绍

记录每天喝了什么，留下每杯饮品的照片和选择，并逐步看见自己的糖分、能量与咖啡因摄入。
