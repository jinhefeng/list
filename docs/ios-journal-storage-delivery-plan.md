# 吃吃喝喝 iOS 全部历史与长期存储开发计划

2026-11-18 · 代码实现完成；Swift 核心测试 72/72 通过，iOS 模拟器目标构建通过；真实用户旧库升级、页面运行与性能/设备验收待完成 · 对应 T6.2 数据与本机仓储、T6.3 页面功能、T6.4 设备验收

## 用户看到的变化

- 打开历史默认显示全部时间范围。列表先显示最近一批，滑到接近底部时自动接上更早的记录，可以一路滑到最早一条。
- 日期筛选由用户主动设置。起始和结束日期都可留空，也可以只设置一端。按本地日期包含所选边界日，清空日期后恢复全部时间范围。记录类型和搜索词可与日期组合。
- 搜索覆盖整个所选范围。日期为空时可以直接搜到多年前的饮品、店名、菜名或备注，即使那条记录还没有出现在列表里。
- 保留本地日期从新到旧、同日时间正序的时间轴。同一时间按稳定记录 ID 排序，从详情返回时保留滚动位置，删除当前记录后停在相邻记录。

目前历史的日期条件在全库解码之后应用，列表构建又会重复读取计算结果。此前 22,000 条模拟器样本的历史结果计算单轮中位数为 375 毫秒。首个可操作画面、照片滚动和带备份的启动按本计划重新测量。[性能审计基线](ios-long-term-performance-audit.md)

## 数据层与兼容

**本机主库。** 已由 `GanfanCore` 管理结构化 SQLite 记录库，提供事务写入、详情、按日期/类型查询、50 条历史分页、按日汇总和附件引用查询。历史不再启动时解码整个 SwiftData 记录集合；列表查询和统计在后台按需返回结果。消费时间、类型、名称、地点、备注及营养指标直接存入有类型的列，多道菜及营养来源拆为关联表并保留顺序、来源和估算状态。继续复用 `JournalRecord` 业务校验和照片文件存储。[现有 iOS 数据边界](ios-development-plan.md#当前接口与边界)

**既有 iOS 数据迁移。** 已实现从 SwiftData 旧库只读分批导入独立 SQLite 暂存库；保留稳定 ID、消费时间、菜品顺序、用户字段、营养快照、照片引用和待备份状态。暂存库会逐条比对可读取记录；无法解码的旧载荷按原始字节保留在兼容表中。只有完整校验通过才原子切换主库，旧库不删除。真实用户旧库升级、中断重试、低空间和设备重启行为仍待隔离资料验收。

**备份与恢复。** 新备份已改为 SQLite 在线快照的单个 `.sqlite` 文件。历史记录、菜品、营养来源、附件引用和无法解码的旧载荷保存在数据库表中；饮品目录、覆盖设置与营养数据包以二进制属性列表写入 SQLite 元数据，不再生成 JSON 记录快照。目录中仍保留既有轻量 `library.json` 标记以兼容资料库识别。原图和自定义 Logo 按文件存放并校验。恢复可读新 SQLite，也兼容旧 JSON 快照；实机/iCloud 文件下载、附件缺失和空库完整恢复尚待验收。[现有备份资料范围](ios-development-plan.md#icloud-drive-备份) · [SQLite 一致快照](https://sqlite.org/backup.html)

## 跨模块约定

| 约定 | 提供方与使用方 | 内容与验证 |
| --- | --- | --- |
| 历史查询 | 数据层提供给历史页 | 输入可选起止日期、记录类型、搜索词和上一批末尾的位置。输出卡片所需字段和下一批位置。用时间和稳定 ID 作分页边界，从数据库找上一有记录的日期组，组内也可分批。保留中文子串及当前名称、品牌、地址、备注和菜名匹配。用同秒跨批、时区变化、多年前唯一命中、空结果和并发编辑样本验证。 |
| 记录与附件 | 数据层与照片存储提供给表单、详情、历史、备份 | 每次提交写入一条记录及其关联数据，照片写好并校验后才保存引用。失败时原记录及其原图可继续打开。通过数据库写入失败、替换照片、删除最后一条及重启后待备份状态验证。 |
| 快照与恢复 | 备份服务提供给备份页与新设备 | 快照和清单来自同一个资料库版本。后台逐个文件复制、校验长度与 SHA-256，再发布快照。仅在写入成功且备份版本仍是当前版本时清除待备份状态。恢复到空库前先在本机暂存并校验，资料齐备才切换。用目录授权失效、缺原图、断网、中断重试及旧 JSON 备份验证。 |

## 完成条件

- **全历史可用。** 起止日期空白时，首屏按固定批量从索引读取最近的记录。用自动化遍历混合饮品和用餐的 22,000 条样本，读到最早一条且无重复 ID 或遗漏。设备上确认跨批滚动和详情返回位置。同日、同秒、跨时区、仅设一端和清空日期都符合约定。搜索能命中未加载的记录，快速改关键词后页面使用最后一次查询。
- **旧资料完整。** 从旧 iOS 库升级后核对每类记录、每道菜、稳定 ID、营养和附件引用。覆盖多图餐食、旧营养字段、待备份状态、低空间、迁移中断及再次启动。新库验证通过后，原有照片和新录入的照片均可离线访问。
- **启动和滚动实测。** 在同一目标 iPhone 上用 Release 比较小库、约 11,000 条和 22,000 条合成库，固定当天与首屏内容。记录冷启动或进入历史到首次可交互的时间、暖切 P50/P95、每批查询读取量、滚动卡顿和峰值内存。固定批量的首屏查询只读取所需范围，日常操作不触发全库解码、原图扫描或备份目录枚举。加测实际 JPEG/HEIC 和已配置备份且有待处理变更。如长时间滑动的内存明显随累计页数增长，为离屏列表批次设缓存上限，并用记录 ID 保留滚动位置。
- **换机恢复实测。** 在空库上分别恢复旧 JSON 和新 SQLite 快照。核对原图、Logo、目录覆盖设置、营养及记录条数。模拟附件下载未完成、低空间和强退重试，验证不会出现部分记录或误报云端上传完成。

自动化验收沿用 IOS-3-10、IOS-3-16、IOS-2-01 至 IOS-2-07，并覆盖相关录入、今日和摄入回归。真机性能、云端文件到达和空库恢复单列证据。[iOS 验收约定](../tests/mvp.test.md) · [今日页设备采样方案](ios-today-performance-plan.md)
