# 干饭手册 — 营养系统 V2（开发分支）

## 目标与交互边界

1. 对没有品牌官方营养表的饮品和菜品，提供带明确标记、假设和粗略数值的离线估算，不再以“0”或空白假装完整数据。
2. 精确匹配来源数据优先；粗估不能覆盖与当前杯型、甜度、温度、冰量完全匹配的正式营养规格。
3. 内置营养数据随 App 发行；在线更新是可选增强，**离线仍可记录并计算**。
4. **AI 接口未配置完整或未启用时，录入页完全没有 AI 识别按钮、提示或占位**。AI 设置入口保留在“更多”页，供用户主动配置。
5. AI 识别只在主动确认后调用用户配置的外部 HTTPS 服务；重新编码为低分辨率 JPEG 去除 EXIF/GPS，API Key 只存在本机 Keychain。

## 在线营养数据包

在「更多 → 营养数据库」填写静态 HTTPS JSON 地址，点击「检查并更新营养数据」。

```json
{
  "schemaVersion": 1,
  "version": "2026.11.14.1",
  "generatedAt": "2026-11-14",
  "entries": [
    {
      "id": "brand.product.variant",
      "nutritionPerUnit": {
        "amount": 100,
        "unit": "ml",
        "energyKcal": 42,
        "sugarG": 7,
        "caffeineMg": 20,
        "proteinG": 1.2,
        "fatG": 0.8,
        "carbohydrateG": 8,
        "sourceType": "estimated",
        "source": "仅作数据结构演示；请替换为真实来源",
        "updatedAt": "2026-11-14"
      }
    }
  ]
}
```

**上述数值仅为格式演示，不是任何品牌的真实营养数据。** 对于远程新增产品，还应提供 `brandID`、`brandName` 和 `name`；新增品牌可通过顶层 `brands` 一起提供。对已有条目按稳定 ID 合并，单个规格由杯型、容量、甜度、温度、冰量和配料构成匹配条件。用户本地覆盖资料优先。

数据包必须使用纯数字分段版本号（如 `2026.11.14.1`），版本须递增；文件上限 5 MB，接口必须为 HTTPS。客户端校验重复 ID、无效数值、缺失的新增产品身份信息、版本回退。验证失败不写入新数据，之前版本继续可用。当前版本仅通过 HTTPS 传输和结构校验；生产开放公共更新前应再采用固定公钥数字签名验证数据包，避免 CDN 或托管账号被盗后的内容篡改。

历史营养快照不被更新自动改写。在线包存入本机独立缓存，不含 API Key，且与个人备份分离；个人已有记录和本地目录修改仍走原先的备份机制。

## 营养来源与估算

- 官方规格：必须对应当前饮品及定制条件；品牌其他杯型的值不能直接标为准确。
- 已录入的每单位营养：在规格确知且没有与甜度不匹配时按容量计算。
- 分类粗估：用于缺少完整资料时。当前为工程初版启发式分类规则，非真实食谱测量；需后续用可信来源校准参数，不应宣称精确。
- AI 粗估：先识别食物和大致克重，再通过本机简化原料表计算。油脂、酱汁、隐藏食材及分量是主要误差来源，结果始终标记为粗估。
- 用户可以修改名称；与名称不一致的旧 AI 结果不会被继续当作该菜的营养值。

已有 `NutritionSnapshot` 增加蛋白质、脂肪、碳水和假设字段，老 JSON 没有这些字段时仍可读取。`MealDish` 增加独立营养快照，编辑页展示每道菜的粗估，详情页展示各菜和整餐营养参考。现有饮品摄入统计仍只计算饮品，避免混入餐食导致历史口径变化。

## 配置第三方视觉 API

「更多 → AI 模型设置」可填写兼容 OpenAI Chat Completions 的 HTTPS URL、支持图片理解的模型 ID、API Key，保存后再开启「启用 AI 拍照识别」。

在菜品编辑页，如果 API 配置完整并已启用、且存在照片，才显示「AI 识别并估算营养」；点击后仍要确认本次照片上传。没配置、关闭开关、删除 API Key、照片为空时不展示入口。图片只在用户主动触发时发送，不在后台自动识别。API 服务商收费、数据处理政策、模型兼容性由用户自己的配置决定。

## 验证要点

`cd ios && swift test`；再在 Xcode 执行 iOS Simulator build 及实际设备流程。回归要覆盖旧饮品/菜品 Codable 读取、旧备份恢复、手动自定义饮品、无 AI API 时隐藏按钮、开启/关闭 AI 后入口变化、拒绝上传后零网络调用、云端更新失败不污染本地、历史快照不被重算、营养来源显示与离线使用。

备注：本开发分支建立在仓库 `main` 的已提交代码上。本地可能未推送的 UI 修改未包含在本分支。
