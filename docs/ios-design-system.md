# 吃吃喝喝 iOS 设计规范

## 设计方向

**餐桌手记／饮食档案。** 首页优先表达“今天记录了什么”，照片、名称和时间构成第一阅读层；快速记录是紧邻的主要操作；日期下方、记录按钮上方以轻量独立摘要展示今日饮品数量和营养合计，不再占用记录列表下方的营养区。界面要像一本容易翻阅、容易补记的个人饮食手记。

## 体验原则

1. **记录先于统计**：首页日期下方的轻量摘要显示饮品总杯数、能量、糖和咖啡因合计；当天记录仍是快速操作之后的主要内容。洞察页承载按日期查看的完整摄入汇总。摘要不展示资料覆盖比，缺失值显示短横线，不把缺失当作零。
2. **真实内容承担视觉表达**：优先使用用户记录中的食物照片、名称、日期和地点。没有照片时用克制、可辨识的类型占位，不制作虚假的食物插画。
3. **减少表面容器**：列表中的记录不默认各自包在卡片里。用留白、细分隔线、对齐和照片建立结构；卡片仅用于有独立信息边界的摘要、表单分组或系统状态。
4. **沿用 iOS 交互**：保留 `NavigationStack`、`Form`、系统日期选择器、照片选择器、系统 tab bar 与系统返回行为。自定义控件必须保持清晰的按压态、选择态和可访问性标签。
5. **内容随环境适配**：文本使用语义字体和动态颜色；布局不得依赖固定单行宽度，用户增加字号后允许内容纵向展开。
   首页进入辅助字号后，记录按钮改为纵向全宽排列，饮品摘要中的三项指标随内容改为纵向排列。常规宽度下首页内容列限制在 680pt 并居中。
6. **导航职责清楚**：底部标签只负责到达顶层页面；首页不再提供通往“历史”或“摄入”的重复导航链接。记录饮品、记录用餐是首页的任务动作，保留为主操作。
7. **二级管理归入“更多”**：顶层页为“今日、历史、摄入、更多”；“更多”用原生分组列表收纳饮品目录、本机存储和备份，不把存储诊断伪装成目录工具。

## 视觉变量

| 用途 | 浅色模式 | 深色模式 | 规则 |
|---|---|---|---|
| 页面底色 | 纸白 `#F6F7F2` | 系统分组背景 | 使用语义色，不在页面内重复写 RGB |
| 主要文字 | 系统 `label` | 系统 `label` | 正文始终保持系统对比度 |
| 品牌深绿 | `#304D36` | `#7AAC7A` | 主要操作、选中态；避免给所有容器上色 |
| 品牌叶绿 | `#5C7852` | `#96BF8C` | 次级图标、轻量强调，不替代正文色 |
| 浅绿表面 | `#E8EFE0` | 深色语义容器 | 次级操作和轻量标记 |
| 卡片/表面 | 白色 | `secondarySystemGroupedBackground` | 仅用于需要与页面底色分层的区域 |
| 分隔线 | 系统 separator | 系统 separator | 细线、低对比，不用描边包围每个列表项 |

品牌图标中的金色只在图标或少量特殊标记里使用；食物照片提供页面所需的丰富色彩。避免大面积渐变、投影和多层描边。

## 字体层级

| 角色 | SwiftUI 字体 | 用途 |
|---|---|---|
| 页面标题 | `.largeTitle.weight(.bold)` 或 `.title2.weight(.bold)` | 首页日期标题、详情页主标题；随 Dynamic Type 放大 |
| 分区标题 | `.title3.weight(.semibold)` | “今天的记录”等分区 |
| 记录名称 | `.headline` | 饮品名、餐馆名 |
| 主要元信息 | `.subheadline` | 品牌、杯型、菜品、地点 |
| 辅助说明 | `.footnote` | 营养来源、简短说明 |
| 次要状态 | `.caption` | 时间、标签；不低于 11pt，不承担关键内容 |

全 App 以系统字体为主。数字可使用 `.monospacedDigit()` 保持变化时的对齐；不在单个页面孤立使用衬线字体或圆体来制造装饰感。避免 `.fixedSize()` 锁死水平宽度；确需保持单行的短值需在较大字号下核验。

## 空间与形状

- 基础间距：4 / 8 / 12 / 16 / 24 / 32pt。
- 页面水平边距：常规 20pt；紧凑列表允许 16pt，但整页保持一致。
- 记录行：照片约 80–88pt；标题与照片顶部对齐；信息最多 3–4 个视觉层级，次要字段移入详情。
- 列表分隔：使用轻量 separator 和垂直留白，避免“每条记录一张卡片”。
- 圆角：照片 12pt；需要浮层的独立表面 16pt；操作按钮 12–16pt。避免全局统一的大圆角。
- 控件高度由内容和 Dynamic Type 决定；不得仅靠固定高度容纳文字。

## 首页信息顺序

1. 标题区域显示“今天”和日期；首页不重复显示 App 名称或 Logo。仅在备份目录未设置、变更待处理或备份异常时显示备份入口；正常状态下隐藏。
2. 日期下方、记录按钮上方展示轻量饮品摘要：顶部显示饮品总杯数，下方并列显示能量、糖和咖啡因合计；不展示各指标的资料覆盖比。辅助字号下改为纵向排列。
3. 两个快速动作：记录饮品、记录用餐。保留明显的触控面积，但不与当天记录争夺主视觉。
4. 当天记录列表：照片、记录名称和时间优先，品牌/杯型/菜品等信息精简呈现。
5. 空状态直接邀请用户开始记录，保留原有记录入口。首页不在记录列表下方重复展示营养汇总卡；单杯明细和按日期查看由“摄入”页承载。

## 状态与反馈

- **空记录**：保持页面结构，展示简短说明和可执行的记录入口；不使用大面积空白占位卡。
- **无照片**：饮品和用餐使用不同类型标识，保持低对比且不伪装成真实图片。
- **营养缺失**：摘要中的缺失营养值显示短横线且不当作零，也不展示资料覆盖比；营养来源与可信度、单杯明细在详情/洞察中完整保留。
- **输入联想**：饮品名称建议和无匹配提示只在名称输入框处于焦点时显示；失焦、点选其他内容或空白处时收起，但保留已输入名称。重新聚焦后继续显示当前查询结果。品牌或名称偏离已选菜单项时，清除旧关联状态。
- **地点搜索**：地图搜索结果选中或地图点选后收起候选列表，保留地图标记和状态说明；编辑查询时清除过期候选，避免旧列表挡住地图。
- **表单主次**：维持小程序约定的字段顺序；名称、杯型、甜度承担主要登记任务。营养资料保持折叠，并用一句说明交代自动计算与自定义饮品的处理方式。
- **备份状态**：正常时不在首页占位；未设置目录、变更待处理或备份异常时显示可读、可访问的提示，并能进入现有备份流程。正在自动写入时不显示短暂的待处理提示。
- **营养图表**：图表只展示记录中实际存在的单杯营养快照；缺失值不绘制为零，并通过覆盖数说明哪些记录有资料。不得用图表表达未经配置的目标或风险阈值。
- **按压与选择**：使用 SwiftUI 原生按钮状态、系统触觉反馈；不要用只在颜色变化时才可辨认的状态。
- **动效**：保存成功后给出系统触觉反馈，新记录以轻量插入动效出现在列表顶部；只用于状态变化或帮助理解的内容转场，并尊重 Reduce Motion。

## 页面结构基线

- **历史时间线**：左侧日期/时间和节点轨道，右侧是照片与记录内容；每天首条显示日期，同日后续条目只显示时间。轨道连接同日记录，不展示单人版本中无意义的用户列。
- **饮品记录顺序**：可点选的留白照片框 → 直接输入饮品名称并实时匹配目录 → 无匹配时继续作为自定义饮品记录 → 品牌（可选）→ 杯型选项 → 甜度、温度；仅选“冰饮”后显示冰量 → 营养快照 → 时间、地点、备注。目录完整浏览保留为次要入口，不阻断主录入流程。
- **照片入口**：空照片使用可点选的虚线框；选择后图片在同一框内预览，并保留更换/移除操作。用餐菜品每道菜提供独立照片框，常规字号采用照片在左、名称在右的行布局，辅助字号下纵向展开。
- **用餐记录顺序**：地址/地图 → 店名 → 用餐时间 → 菜品（每道菜照片与名称、排序、添加/移除）→ 备注。地点和菜品不合并成一张无法扫描的大卡片。
- **“更多”页面**：饮品目录属于饮品资料；本机存储与备份属于数据管理。目录页工具栏只保留与目录本身有关的操作。

## 无障碍与验证

- 保留系统语义色并检查浅色、深色、高对比和减少透明度环境。
- 使用系统动态字体；验证默认、较大及最大辅助字号下的换行、滚动和按钮可点性。
- 关键状态使用文字或图标辅助，不单靠颜色传达。
- 检查 VoiceOver 标签、按钮触控面积、截断和照片说明。
- 每屏修改后保存模拟器或真机截图，并检查正常态、空态、按压/选择态。记录具体设备、外观、字号和待修问题。

## 分屏实施顺序

1. 首页：记录优先的信息层级、日期下方的轻量饮品摘要、快速记录和当天列表；不在列表下方重复展示营养区。
2. 饮品与用餐记录表单：按填写顺序整理分组，保留业务字段和原生输入控件。
3. 历史与筛选：统一列表行、日期层级和筛选入口。
4. 记录详情与照片浏览：加强记录档案感，完整保留营养来源、地点、备注和编辑/删除操作。
5. 洞察与菜单：明确各自任务，移除重复汇总，统一颜色、字体和状态。
6. 地点选择、备份和存储诊断：保留系统交互，补齐深色、高字号和反馈状态。
