# 饮品与用餐记录小程序

一个原生微信小程序 MVP，用于记录饮品和用餐；饮品与吃饭有各自的录入入口，并在同一条历史时间轴中按时间查看。饮品摄入统计只计算饮品。

## 本地开发

1. 使用微信开发者工具打开本目录。
2. 项目配置中的 `touristappid` 是占位值；提交或上传到微信前，替换为自己的小程序 AppID。
3. 在终端运行 `npm test`，执行饮品记录业务逻辑和页面表单行为测试。

## 当前功能

- 今日饮品与用餐记录；历史时间轴将两类记录合并展示，并支持按时间范围、登记用户多选筛选。
- 分开的饮品和吃饭录入入口；用餐记录包含地图地址、店名、自动时间和多道菜品，每道菜可有自己的照片。
- 菜单品牌/款式搜索，选择全局杯型、糖度、温度和冰量，并填写备注；容量统一在清单维护的全局设置中配置，记录页不展示容量；不记录小料。
- 杯型从小杯、中杯、大杯、超大杯中选择；冰量与温度合并为一组单层选项，不记录小料。
- 饮品记录默认使用表单打开时的时间，并优先读取照片拍摄时间；用餐记录默认使用打开记录页时的时间。两类记录都可修改时间。
- 地点可从地图选择名称和地址，也可手动修改；用餐记录在地址外单独保存店名。
- 历史记录按时间顺序逐条展示，日期、时间和记录人位于轨道同侧；照片缩略显示并可点击放大。
- 从相册或相机选照片，并在设备内保存。
- 自定义品牌与饮品；用户输入的营养数值标记为估算值。
- 按精确匹配的规格与选项展示官方数据或估算数据；缺少匹配数据时显示“暂无数据”。
- 今日能量、糖量、咖啡因汇总，以及数据来源计数。
- 编辑和删除自己的本地饮品及用餐记录。

## 数据范围

内置目录当前包含 31 个品牌、447 个候选饮品名：按 2026 茶饮榜单前 15、咖啡榜单前 15，再加星巴克建立首期品牌范围。**这不是完整菜单**：当前没有品牌达到全菜单核验标准；4 个品牌还没有可靠的大陆在售菜单来源，猫屎咖啡目前只有广州单店推荐样本，其他品牌也有未检查分页。品牌官网和第三方菜单汇编只用于补充待核验名称，不代表杭州、常州或上海的淘宝闪购具体门店在售，也不包含经核实的杯型、糖度或营养数据。

覆盖台账在 [data/catalog-coverage.json](data/catalog-coverage.json)，运行 `npm run catalog:coverage` 可查看每个品牌的候选数、来源自报数量、已检查分页和缺口状态。第三方汇编自称信息收集自互联网，数量会变化且有页面混入餐食；其数量只作核对线索，不能当作完整性证明。实际在售情况仍需按杭州上城、常州天宁和上海黄浦的中心城区样本门店逐店核验。旧饿了么 H5 页面不作为当前菜单来源。

菜单批量导入、字段说明和远程目录更新配置见 [docs/catalog-data.md](docs/catalog-data.md)。远程更新地址尚未配置，应用继续使用本地菜单。

首页顶部可进入“饮品清单维护”，按品牌、种类和关键词查找；默认不列出饮品，可点“展示全部饮品”查看全目录。列表每批显示 30 条并可继续加载。种类可留空；营养输入统一按每 100 ml，记录时系统读取清单页设置的全局杯型容量折算本杯摄入量；用户界面只显示杯型名称。容量可暂时留空，未配置时营养基准仍会保存，补齐容量后再折算。已保存的完整营养快照不受目录后续修改影响；记录页新建的自定义饮品会自动加入本机清单，之后可再次选择。饮品若已被历史记录引用则不能删除；未被引用的饮品需二次确认后删除。当前目录修改只保存在本机；远程目录配置后，本机新增项和本机覆盖内容会在更新时保留。

记录和照片仅保存在运行小程序的设备上，没有账号登录、记录云存储或跨设备记录同步。菜单目录支持可选 HTTPS 更新；当前尚未配置远程地址。
